Модель на компьютере или по API

Автономные правила работают без сети. Для смыслового анализа выберите локальную модель или сервис с API.

Для Gemini можно использовать {model} в адресе. Для локальной модели допускается HTTP на localhost. Остальные адреса — HTTPS.
Хранится только в памяти вкладки. Не включается в HTML, отчёт или сеанс.

Подключение ещё не проверялось.

Числовые строки проверяются автономным модулем. Модель получает уникальные пары текста; повторные вхождения сохраняются в привязках. Совместимость определяется форматом API, а не названием модели. Сервисы с авторизацией через облачную подпись требуют своего шлюза.

Подстановки: {{model}}, {{system}}, {{user}}, {{max_tokens}}. Если подстановка занимает всё значение, её тип сохраняется.
Английский термин = предпочтительный перевод. Дополняет встроенный технический профиль.

Профиль содержит обобщённые правила и шаблоны перевода, подготовленные по предыдущей экспертной сверке. Значения размеров и давлений берутся из загруженного оригинала. Это предметная адаптация, а не универсальная языковая модель.

Изменение провайдера или адреса сбрасывает разрешение. Для GitHub Pages провайдер должен разрешать CORS. Облачный ключ общего сервиса храните в защищённом шлюзе. При работе без интернета загрузите модель в Ollama заранее и откройте HTML локально.

Процесс проверки

  1. Загрузите два DOCX и проверьте сопоставление. Сохраняются ссылки на часть файла и абзац.
  2. Запустите локальные правила. Они выявляют изменение числа/знака/порядка значений, отсутствие перевода, известные терминологические ошибки и потерю единиц.
  3. Подключите модель и разрешите передачу текста. Каждый пакет проходит основной анализ и, по выбору, повторную проверку. Сбой пакета не считается успешной проверкой; повторный запуск продолжает незавершённые пакеты.
  4. Отредактируйте предложения и примите нужные. Повторы объединяются, но ссылки на все случаи сохраняются. Обоснование должно быть проверяемым.
  5. Скачайте Excel с четырьмя требуемыми столбцами или копию DOCX. Исходные файлы не изменяются.

Как вносятся правки в Word

Заменяются только точные, однозначные цитаты в согласованных местах. Исходный архив, таблицы, изображения и свойства абзацев сохраняются. Новый текст наследует формат первого затронутого фрагмента; исходное смешанное оформление внутри заменённой цитаты может упроститься. Сложные поля, формулы, гиперссылки и абзацы с исправлениями Word исключены из автоматической замены. Конфликты и блокировки останавливают экспорт и перечисляются в журнале. Экспорт — обычная исправленная копия, без режима рецензирования.

Границы качества

Автономный модуль сверяет числа, даты, обозначения и применяет технический профиль ASME/WRC. Правила профиля подготовлены на основе предыдущей экспертной проверки этих документов; повторный тест не является независимой оценкой на новых данных. Статические правила не понимают весь смысл. Качество смысловой проверки зависит от выбранной модели, словаря и сопоставления. Равенство с экспертной проверкой не гарантируется. Изображения, формулы OMML и вложенные объекты не проходят OCR; нормативную и инженерную правильность самого оригинала инструмент не подтверждает. Перед выдачей проверяйте Word визуально.

Почему нужен сервер для общей версии

GitHub Pages публикует статические файлы. Закрытый ключ нельзя скрыть внутри HTML. Для команды используйте аутентифицированный шлюз с разрешённой моделью, лимитами и ограничением источника запросов. Личный совместимый API можно подключить прямо, если он разрешает CORS и это допускает ваш порядок работы.

Сохранение данных

Автосохранения и аналитики нет. DOCX и ключ находятся в памяти вкладки. JSON сеанса содержит текст документов и решения — храните его как сами документы. После перезагрузки заново загрузите файлы и сеанс. Встроенная библиотека JSZip 3.10.1 распространяется по лицензии MIT; файл работает без CDN.

Идея многослойной проверки изучена на примере исходного корректора. Этот инструмент реализует двуязычное сравнение; код интерфейса и правил написан заново.
