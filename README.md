# Сверка 2.0

Автономный инструмент сверки технического перевода с английского на русский: два DOCX, предложения исправлений, обоснования и экспорт Excel. Интерфейс — чёрная японская матрица с падающими белыми иероглифами. Анимацию можно выключить.

## Запуск

Откройте `index.html` или опубликованную страницу GitHub Pages. Загрузите оригинал и перевод, проверьте сопоставление абзацев и нажмите **Запустить проверку**.

Без отметки **Добавить смысловую проверку выбранной моделью** обработка выполняется в браузере без отправки текста на сервер. Внешние библиотеки и шрифты с CDN не загружаются.

## Возможности

- Сверка числовых последовательностей, знаков, дат, единиц и обозначений.
- Технический профиль ASME/WRC и пользовательский словарь.
- Предложения перевода с точными цитатами и привязкой к абзацам.
- Ручное принятие, редактирование и отклонение правок.
- Экспорт XLSX с четырьмя столбцами, сохранение сеанса JSON и исправленная копия DOCX для простых однозначных замен.
- Подключение Ollama, LM Studio, OpenAI Chat Completions/Responses, Claude, Gemini и настраиваемого JSON API.

## Работа с LLM

В настройках выберите протокол, укажите адрес сервера, имя модели и ключ, если он необходим. Для локальной Ollama стандартный адрес — `http://127.0.0.1:11434/api/chat`. Модель необходимо установить отдельно. По умолчанию указана `qwen3:4b`.

Ключ находится только в памяти вкладки. Для общего сайта храните секрет провайдера в защищённом серверном шлюзе. Прямой запрос из браузера требует разрешения CORS от сервиса. Обращение к локальной модели из HTTPS зависит от политики браузера; при необходимости используйте скачанный HTML на localhost.

В расширенных настройках доступны заголовки, JSON-шаблон запроса и путь к тексту ответа. Сервисы с облачной IAM-подписью или нестандартным потоковым протоколом требуют своего шлюза.

## Границы проверки

Технический профиль подготовлен по экспертной сверке расчётных документов ASME/WRC. Регрессионное воспроизведение известных ошибок не является независимым доказательством качества на новых текстах. Автономные правила не заменяют языковую модель и редактора. Небольшие локальные LLM также могут ошибаться.

Сопоставление абзацев нужно проверить. Текст на изображениях, формулы OMML и вложенные объекты не распознаются. Инженерная правильность оригинала не оценивается. Для многоабзацных правок, полей, гиперссылок, формул и сложного оформления могут понадобиться ручные изменения в Word.

Основной Excel содержит предложения с заполненным исправлением. Кандидаты без надёжного перевода остаются в интерфейсе и JSON-сеансе. Исходные файлы не изменяются.

## Основание и зависимости

Инструмент сделан на основании [«Корректора документов»](https://luxtendebant-ux.github.io/error_ch_v.1.3/). Двуязычная сверка, технический профиль и новый интерфейс разработаны отдельно.

Встроенная JSZip 3.10.1 распространяется по лицензии MIT; уведомление о лицензии сохранено в коде библиотеки. Закрытые документы, результаты пользовательских проверок, ключи API и файлы моделей не входят в репозиторий.
